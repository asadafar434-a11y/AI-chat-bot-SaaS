# Тендерный юрист — интерфейс продукта

Вид — прототип в стиле Figma Make (исходник Make лежит в «Улучшение прототипа из GitHub» как есть). Данные и логика —
настоящие: общий код приложения из `web/src` (`@/…` — это `web/src`), хранилище закупок в браузере (IndexedDB). Документы
читает и к ИИ обращается сервер из папки `web`: запросы `/api` идут к нему (`vite.config.ts`).

```bash
npm --prefix web run dev -- --port 3001                          # сервер: документы, ИИ, файлы Word (нужен ключ ИИ — web/.env.local)
npm --prefix design-system/prototype run dev -- --port 3000      # интерфейс: http://localhost:3000
npm --prefix design-system/prototype run build                   # dist/prototype.html — одна страница
npm --prefix web run build:host                                  # экран → web/public/product, затем сервер: для хостинга и для start:local
npm --prefix web run start:local                                 # продукт одним адресом: http://localhost:3000 (вместо пары выше)
npm --prefix design-system/prototype run typecheck
```

Шрифты Geist и Geist Mono — файлы в `src/fonts` (лицензия SIL OFL), а не Google Fonts: сервер на хостинге не пускает шрифты с чужих сайтов.

Интерфейс открывают на `localhost:3000`, сервер — на `3001` (другой адрес сервера — переменная `API_ORIGIN`). Закупки и документы
лежат в браузере по адресу страницы, поэтому адрес менять нельзя — данные прежнего адреса не видны на новом (копия данных — в
«Профиле компании»).

## Что где

| Экран | Файл (вид → данные) | Что делает |
|---|---|---|
| Согласия | `real/consent.tsx` | два согласия перед началом работы; тексты — страницы `/consent`, `/privacy`… сервера |
| Мои закупки | `components/TendersDashboard.tsx`, `real/tenders.ts` | закупки из браузера, статусы, «Отметить поданной», удаление, «Посмотреть на примере» |
| Путь заявки | `App.tsx`, `real/purchase-provider.tsx` | 5 шагов, шапка закупки; правки сохраняются сами |
| Загрузка | `StepUpload.tsx`, `real/upload.tsx`, `DocSearch.tsx` | PDF, Word, Excel, ZIP, сканы; ИИ выписывает требования; поиск по словам в документах закупки |
| Анализ | `StepAnalysis.tsx`, `real/analysis.tsx` | «что подать и как выполнить» по `web/src/lib/fulfillment.ts` |
| Цена | `StepPricing.tsx`, `real/pricing.tsx` | «до какой цены снижаться» — `web/src/lib/price-floor.ts`; цену можно поставить в заявку |
| Проверка | `StepReview.tsx`, `real/review.tsx`, `CastCard.tsx`, `OwnCheck.tsx` | карта полей, жёлтые места заявки, состав исполнителей, проверка своей заявки файлом |
| Пакет | `StepPackage.tsx`, `real/package.tsx` | файлы Word или PDF по одному и ZIP, список «Что требует заказчик»; оплата и специалист — «скоро» |
| Профиль компании | `Profile.tsx` | реквизиты, образцы и документы, копия данных, удаление всего |
| Тарифы | `Tariffs.tsx` | цены из `web/src/lib/pricing.ts`; покупка — «скоро» |
| Чат | `ChatAssistant.tsx`, `real/assistant.ts` | вопросы к ИИ по документам открытой закупки или общие, ответ потоком |
| Поиск, история | `TenderSearch.tsx`, `BidHistory.tsx` | «скоро»: пример того, как будет |

Скачивание файлов заявки — `web/src/lib/use-application-files.ts`: его используют и этот интерфейс, и приложение на Next.
Word и PDF собираются из одного описания документа (`web/src/lib/tp-doc-model.ts`): `tp-docx.ts` рисует его в Word, `tp-pdf.ts` — в PDF (библиотека pdfmake, шрифт Roboto).

## Что пока не работает

- Оплата, проверка специалистом, пересчёты ИИ с лимитами и формат ODT — помечены «скоро».
- Поиск по площадкам, итоги торгов, импорт по ссылке ЕИС — «скоро».
- В «Цене» нет таблицы позиций: цен по позициям в документах закупки бывает нет, выдумывать их нельзя.
- Вероятность победы не показывается: без истории торгов заказчика её нечем честно посчитать.
- Хостинг не выбран. Способ выкладки решён: экран отдаёт сам сервер с главной страницы, у продукта один адрес — `npm --prefix web run build:host`,
  подробности — «Один адрес для экрана и сервера» в [README сервера](../../web/README.md).
