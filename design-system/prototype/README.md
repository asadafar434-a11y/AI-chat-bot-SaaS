# Тендерный юрист — интерфейс продукта

Вид — прототип в стиле Figma Make (исходник Make лежит в «Улучшение прототипа из GitHub» как есть). Данные и логика —
настоящие: общий код приложения из `web/src` (`@/…` — это `web/src`), хранилище закупок в браузере (IndexedDB). Документы
читает и к ИИ обращается сервер из папки `web`: запросы `/api` идут к нему (`vite.config.ts`).

```bash
npm --prefix web run dev -- --port 3001                          # сервер: документы, ИИ, файлы Word (нужен ключ ИИ — web/.env.local)
npm --prefix design-system/prototype run dev -- --port 3000      # интерфейс: http://localhost:3000
npm --prefix design-system/prototype run build                   # dist/prototype.html — одна страница
npm --prefix web run build:host                                  # экран → web/public/product, затем сервер: для хостинга и для start:local
npm --prefix web run start:local                                 # продукт одним адресом: http://localhost:3000 (вместо пары выше)
npm --prefix design-system/prototype run typecheck
npm --prefix design-system/prototype test                        # компоненты в разметку (без браузера): роли, подписи, вывод ответа ИИ
```

Шрифты Geist и Geist Mono — файлы в `src/fonts` (лицензия SIL OFL), а не Google Fonts: сервер на хостинге не пускает шрифты с чужих сайтов.

Интерфейс открывают на `localhost:3000`, сервер — на `3001` (другой адрес сервера — переменная `API_ORIGIN`). Закупки и документы
лежат в браузере по адресу страницы, поэтому адрес менять нельзя — данные прежнего адреса не видны на новом (копия данных — в
«Профиле компании»).

## Доступность

Проверено 01.10.2026 (QA-аудит): ширины 320–1280 px, светлая и тёмная тема, клавиатура, диктор (роли и подписи).

- Окна (`Modal` и меню на телефоне) — `role="dialog"` с `aria-modal` и названием; фокус уходит внутрь окна, Tab ходит по кругу,
  Escape закрывает, фокус возвращается туда, откуда окно открыли (`useDialogFocus` в `ui.tsx`; логика — `web/src/lib/focus-trap.ts`).
- Ошибки — `role="alert"`, пометки — `role="status"`; у каждого поля есть подпись (`label` или `aria-label`), у иконочных кнопок — имя.
- Контраст текста — не ниже 4,5 : 1 в обеих темах. Подпись, «готово» и «ошибка» в светлой теме чуть темнее, чем в Make
  (`--muted-foreground`, `--success`, `--danger` в `src/index.css`); `web/src/lib/contrast.test.ts` не даст вернуть бледные цвета
  при следующем переносе из Make.

## Что пока не работает

- Оплата, проверка специалистом и пересчёты ИИ с лимитами — помечены «скоро». Когда документы закупки изменились после составления ТП,
  приложение только предупреждает («требует проверки», `web/src/lib/doc-changes.ts`); составить ТП заново с учётом правок участника — тот же «Пересчитать с ИИ».
- Адрес цитаты («Место в файле») есть у файлов, загруженных после этого обновления. У прежних страницы узнаются по меткам PDF,
  а пункт и раздел — по виду строк; полный адрес даст повторная загрузка файла. У сводки закупки (название, цена, срок) цитаты нет — адреса тоже.
- Страницы Word — по разметке, которую оставил сам Word (в адресе — «≈ стр.»): на другом компьютере они могут сместиться. Таблицы PDF без линий сетки читаются
  как обычный текст; слова, набранные «в разрядку» (Н а и м е н о в а н и е), остаются как в файле.
- Требования: обязательность, тип, срок, как проверить и чем подтвердить выписывает модель, числа и слова «не менее», «не более» код читает из цитаты сам
  (`web/src/lib/conditions.ts`, `requirement-engine.ts`). Новая инструкция для модели ещё не проверена живым запросом — нужен платный прогон на одной закупке
  (после «включи» и цены). Числа читаются для границ «не менее», «не более», «от … до …», размеров «3×2» и сроков «в течение …»; необычные формулировки
  остаются в цитате, но числом не выделяются. Закупки, выписанные раньше, получают числа из цитат сразу, остальные поля — после повторного разбора.
- Заказчик требует — участник предлагает: ИИ не подставляет за участника число с границы заказчика. После ответа модели код заменяет такое число пустым
  местом «[число, не меньше 150]» (`web/src/lib/tp-guard.ts`); прежние черновики ТП с подобранным ИИ значением получают пометку «значение подобрал ИИ — подтвердите».
  Охрана ловит число, равное границе, и число с той же единицей, что у границы; число с другой единицей и без границы в документе она пропустит — это сверяет человек.
- Поиск по площадкам, итоги торгов, импорт по ссылке ЕИС — «скоро».
- В «Цене» нет таблицы позиций: цен по позициям в документах закупки бывает нет, выдумывать их нельзя.
- Вероятность победы не показывается: без истории торгов заказчика её нечем честно посчитать.
- Хостинг не выбран. Способ выкладки решён: экран отдаёт сам сервер с главной страницы, у продукта один адрес — `npm --prefix web run build:host`,
  подробности — «Один адрес для экрана и сервера» в [README сервера](../../web/README.md).
