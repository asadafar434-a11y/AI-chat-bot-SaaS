## Порядок этапов

Этот порядок обязателен: каждый следующий этап опирается на то, что появилось в предыдущих. Нарушение
порядка ломает откат и верификацию.

| Этап | Содержание | Таблицы БД | Ключевое ограничение |
|---|---|---|---|
| **S0** | Архитектурный контракт (этот документ) | нет | код не пишется |
| **S1** | Фундамент PostgreSQL + Prisma | 11 (см. [data-model.md](data-model.md) §2) | только аддитивные миграции |
| **S2** | Auth.js и tenancy | +4 (см. [data-model.md](data-model.md) §2.1) | **требует S1**: сессии в БД |
| **S3** | Экспорт/импорт данных из IndexedDB | — | только через существующий формат копии |
| **S4** | Чтение с сервера за флагом + dual-read | — | IndexedDB цел и остаётся источником |
| **S5** | Запись на сервер | — | только в окне стабилизации откат |
| **S6** | Объектное хранилище S3 | — | метаданные `Document` уже созданы в S1 |
| **S7** | Аудит `AuditEvent` | — | таблица создана в S1, наполняется с S7 |

| **S11** | Финальный переход | — | удаление легаси — только с отдельной подписью |

Полное описание каждого этапа и его отката — в [migration-and-rollback.md](migration-and-rollback.md) §3.

## Границы этапа

Сделано на этом этапе:

- спроектирована целевая архитектура;
- зафиксированы состав и порядок создания всех таблиц, роли, модель профиля, правила изоляции, схема
  развёртывания, порядок этапов и откат для каждого этапа, стратегия миграции;
- составлен инвентарь кода, который запрещено переписывать.

Не сделано намеренно:

- не установлены зависимости (в `web/package.json` не добавлено ни одной);
- не создан `prisma/schema.prisma` — модель описана в [data-model.md](data-model.md) как предложение;
- не созданы и не запущены миграции Prisma;
- не изменена схема базы данных;
- не реализован Auth.js и не спроектирован его полный поток сессий (требует S1);
- не реализована миграция данных;
- не изменены существующие route handlers `web/src/app/api/**`;
- не изменён IndexedDB, не менялись и не удалялись браузерные данные;
- бизнес-логика `web/src/lib` не переписывалась;
- ничего не запушено.

## Что зафиксировано, а что ещё нет

Зафиксировано (менять только через новый ADR):

границы слоёв, правило зависимостей, **полный перечень таблиц и порядок их создания**, порядок этапов
S0–S11, раздельная модель профиля (корпоративные реквизиты в `Organization`, персональные данные и личные
настройки в `User`), модель ролей и memberships, правила tenant-изоляции, вход по email+паролю с
приглашениями и сбросом пароля, разделение S3/PG для документов, очередь pg-boss без Redis, схема
резервных копий и восстановления, формат логов, Docker-топология, правила отката для каждого этапа, запрет
на переписывание доменной логики.

Не зафиксировано (сознательно отложено):

- конкретный RF-провайдер S3 (Yandex Object Storage / Selectel / Cloud.ru — выбор владельца);
- конкретный RF-провайдер ВМ (AvanCloud / Selectel / Timeweb);
- политика паролей и параметры 2FA (2FA — точка расширения, не часть Stage 11);
- тарифная модель и момент ввода ЮKassa;
- тексты соглашений и политик для многоарендного режима;
- SLA и конкретные числовые цели RPO/RTO (требуют решения владельца, значения по умолчанию предложены в [operations.md](operations.md));
- итоговое решение по внешнему мониторингу — требуется legal/privacy review, см.
  [operations.md](operations.md) §2.4.

Следующий этап — **S1, фундамент PostgreSQL**. Auth.js идёт после него отдельным этапом S2 и до него не
проектируется в деталях.
