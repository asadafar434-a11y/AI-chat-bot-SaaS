# S10 — Payment Provider Discovery

**Статус: discovery только. Провайдер НЕ выбран владельцем. Реализация платежей не начиналась.**

Документ фиксирует исследование и сравнение платёжных провайдеров для проекта. Он не является
решением о выборе провайдера. См. также [s10-payment-provider-freeze.md](s10-payment-provider-freeze.md).

## Контекст проекта

- Бизнес в РФ, валюта RUB; клиенты — поставщики (юрлица/ИП) по 44-ФЗ/223-ФЗ.
- Текущая модель — разовые платежи за заявку + возможные пакеты/допы; recurring — опционально на будущее
  («Платите за заявку, а не за подписку»).
- Backend: Next.js + PostgreSQL/Prisma, Auth.js, organization tenancy, S7 audit, S8 jobs, S6 storage.
- Платежи должны быть **tenant-scoped** (Organization) и **server-authoritative**; платёжные данные и секреты —
  только в РФ-инфраструктуре (152-ФЗ, локализация).

## Shortlist (5)

1. ЮKassa (YooKassa, ЮMoney) — РФ
2. CloudPayments — РФ
3. Т-Банк (интернет-эквайринг Т-Бизнеса / T-Kassa) — РФ
4. Robokassa — РФ
5. Точка Банк API (Tochka) — РФ

Исключены по regulatory: **Stripe, Paddle, LemonSqueezy, PayPal, Adyen** — не обслуживают бизнес в РФ
(санкции; Stripe «does not support users located in Russia», Mir не поддерживается). Дополнительно
рассматривались Prodamus и PayKeeper (Prodamus силён в recurring/EdTech, но дороже; PayKeeper — низкая
комиссия, ограниченнее экосистема).

## Плюсы/минусы

- **ЮKassa**: + самый распространённый РФ-агрегатор, дешёвый СБП, `Idempotence-Key`, офиц. Node SDK,
  автоплатежи, 54-ФЗ; − тариф не публичный, чеки — отдельный сервис.
- **CloudPayments**: + зрелый рекуррент, виджет без редиректа, HMAC-подпись вебхуков, PCI DSS, sandbox;
  − ставка по нише/обороту, экосистема меньше.
- **Т-Банк**: + банковский эквайринг, тестовый терминал, OpenAPI, бесплатная касса, широкий набор способов;
  − нужен счёт в банке, SberPay через свою форму не поддерживается, тариф индивидуальный.
- **Robokassa**: + публичная сетка тарифов, 130+ интеграций, чеки включены, рекуррент/холдирование;
  − рекуррент по согласованию, API/подписи старее (MD5).
- **Точка API**: + банковский API, песочница, подписки/вебхуки; − подписки только карты, возврат только в
  интернет-банке, ограничения графика, нужен счёт в Точке.

## Regulatory / KYC

- Все кандидаты — РФ-провайдеры; требуется российское юрлицо/ИП, расчётный счёт, KYC/онбординг, скоринг.
- **54-ФЗ**: при приёме платежей от физлиц/картами нужны фискальные чеки; для расчётов между юрлицами
  по безналу чек, как правило, не требуется.
- **Cross-border/санкции**: зарубежные провайдеры для РФ-юрлица не подходят.
- Секреты провайдера — только env/secret manager; карты/CVV не хранить; платежи — tenant-scoped в РФ.

## Какие возможности потребуют отдельной реализации

`Payment`/`Transaction` (tenant-scoped) + миграции; webhook endpoint + адаптер верификации подписи
(`PaymentAdapter`); хранилище идемпотентности и webhook-событий; маппинг Organization → customer
(+ subscription state при recurring); 54-ФЗ/чеки; refund flow с ролью owner; background reconciliation (S8);
audit-события (S7); fulfillment; customer portal; secrets/env.

## Рекомендация (кандидаты, не выбор)

Для этого проекта в первую очередь стоит детально оценить **ЮKassa** и **CloudPayments** (наилучшее
сочетание доступности в РФ, RUB, разовых и рекуррентных платежей, вебхуков с подписью, идемпотентности,
sandbox и Node/TS-совместимости). **Т-Банк** — сильный банковский альтернативный кандидат.
Окончательное решение — за владельцем.

## Требуемые решения владельца перед реализацией

1. Провайдер. 2. Способы оплаты. 3. Одноразовые/подписки/оба. 4. Refunds. 5. Валюты (вероятно RUB).
6. Страна/юрлицо и KYC. 7. 54-ФЗ/чеки и налоговая модель.
