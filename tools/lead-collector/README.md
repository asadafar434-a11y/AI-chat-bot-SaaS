# Сборщик базы поставщиков из реестра контрактов ЕИС

Отдельный инструмент для поиска клиентов «Тендерного юриста». Код продукта (`web/`) и его базу данных **не трогает**.
Ничего не рассылает и никому не звонит.

> ## ⚠ ТРЕБУЕТ ПРОВЕРКИ ЮРИСТОМ
> Контакты индивидуальных предпринимателей (ИП) — **персональные данные физлица** (152-ФЗ). До проверки юристом нужно решить:
> 1. **Правовое основание хранения** контактов ИП (и цель обращения к ЕИС, которую ЕИС требует указать при получении токена).
> 2. **Порядок первого контакта.** Реклама по почте и телефону — только с предварительного согласия адресата (ст. 18 закона «О рекламе»).
>    До согласия по этим контактам не писать и не звонить. Статус «согласие получено» ставьте только при документально подтверждённом согласии.
> 3. Срок хранения и порядок ответа на обращения людей (удаление — команда `delete`).
>
> Ничего из этого сборщик не решает за вас. Заключения «соответствует 152-ФЗ» здесь нет.

## Два способа получить данные

1. **С сайта ЕИС, без токена и регистрации** (`collect-web`) — основной. Проверен 20.10.2026 в браузере на 10 настоящих карточках контрактов:
   в блоке «Информация о поставщиках» есть наименование, ИНН, КПП (у ООО), адрес места нахождения, почтовый адрес, телефон и почта; у ИП — ФИО
   с пометкой «Индивидуальный предприниматель» и ИНН из 12 цифр. **ОГРН в карточке нет.** Регион отдельно не указан — берётся из адреса.
   Собираются **и ООО, и ИП** (ИП помечены).
2. **Официальный сервис выгрузки `getDocsIP`** (`collect`) — нужен токен, формат не проверен; запасной вариант.

Фильтры поиска, проверенные в браузере: дата размещения (`publishDateFrom/To`), дата заключения (`contractDateFrom/To`), минимальная сумма
(`contractPriceFrom`), формат дат ДД.ММ.ГГГГ. Фильтр «стадия контракта» ломает поиск (пустой список) — не используется.

**Важно про «вчера».** Контракты попадают в реестр с задержкой в несколько дней: за вчерашнюю *дату заключения* в реестре почти ничего нет
(19.10.2026 — 3 записи). Поэтому по умолчанию ищем по **дате размещения** (`--date-kind published`); по дате заключения — `--date-kind signed`.

**Объём.** За один день размещения — более 6 400 контрактов от 100 000 ₽ (14.10.2026). При паузе 4 с на карточку это около 7 часов. Поэтому
за запуск читается не больше `--max-cards` карточек (по умолчанию 200); уже сохранённые контракты повторно не запрашиваются, повторный запуск
продолжает с места остановки. Для узкой выборки используйте `--min-amount`.

**Доступ из Python.** Сайт открывается у вас через VPN в Chrome, а Python его напрямую не видит (проверено: тайм-аут). Нужен прокси/VPN на весь
компьютер или переменная `HTTPS_PROXY` с адресом прокси, либо запуск на машине с доступом к сайту. Капчи и блокировки не обходим: при отказе
сборщик останавливается.

**Режим «VPN только в Chrome»** (проверен 20.10.2026): страницы читает Chrome, наш код принимает их локально и разбирает.
1. В терминале: `python -m lead_collector receive` (слушает только 127.0.0.1).
2. В Chrome с VPN откройте результаты поиска (адрес — как в `web.py`, `search_params`; пример:
   `https://zakupki.gov.ru/epz/contract/search/results.html?morphology=on&fz44=on&sortBy=PUBLISH_DATE&pageNumber=1&sortDirection=false&recordsPerPage=_50&publishDateFrom=19.10.2026&publishDateTo=19.10.2026&contractPriceFrom=100000`),
   вставьте в консоль `chrome/fetch-cards.js`, дождитесь `window.__prog.finished === true`.
3. `python -m lead_collector parse-folder data\inbox --min-amount 100000` — разбор, база и выгрузка.

**Пробный прогон 20.10.2026** (размещение 19.10.2026, от 100 000 ₽, первые 40 карточек, регион не фильтровался): чтение в Chrome 161 с (пауза 3,5 с),
разбор 26 с (из них выгрузка Excel); 40 контрактов → 23 поставщика (18 ООО, 4 ИП, 1 другое юрлицо); у всех есть телефон и почта; регион определился у 22 из 23;
повторный разбор новых записей не дал.

## Что проверено, а что нет (честно)

- Работают и проверены тестами на **выдуманных** данных: хранение, удаление дублей по ИНН, повторный запуск, удаление по ИНН, статусы, выгрузка в CSV и Excel.
- Разбор карточек (`cards.py`) проверен на настоящей разметке в браузере; тесты — на выдуманных данных той же раскладки.
- **Не проверено: фильтр по региону заказчика** (`customerPlaceCodes`: формат кода неизвестен), чтение сайта из Python (нет доступа), официальный сервис:
  - формат запроса к сервису `getDocsIP`, значения подсистемы и типа документа (`EIS_SUBSYSTEM`, `EIS_DOCUMENT_TYPE`);
  - названия тегов в настоящих XML контрактов (таблица `TAGS` в `lead_collector/parser.py`) — поэтому телефон, почта, КПП и регион поставщика могут оказаться пустыми, пока таблицу не сверят с настоящим контрактом;
  - смысл даты в запросе (дата публикации или заключения) — фильтр по дате заключения сборщик применяет сам;
  - коды регионов для режима «все» (`REGION_CODES` в `config.py`);
  - «Регион поставщика» пока не определяется (пусто), «Регион заказчика» — это регион из запроса.

## Установка

1. Нужен Python 3.12 (на этом компьютере уже стоит).
2. В папке `tools/lead-collector`:
   ```bash
   python -m pip install -r requirements.txt
   ```
3. Токен ЕИС: получите сами на https://zakupki.gov.ru/pmd/auth/welcome через Госуслуги («Регистрация нового потребителя машиночитаемых данных»,
   «Физическое лицо, ИП»). Скопируйте `.env.example` в `.env` и впишите `EIS_TOKEN=...`. Файл `.env` в git не попадает; токен никому не показывайте.

## Запуск

Все команды — из папки `tools/lead-collector`. Если `python` не находится, откройте новое окно терминала.

Каждый день, с сайта без токена (вчерашний день размещения, контракты от 100 000 ₽):
```bash
python -m lead_collector collect-web --min-amount 100000
```

Через официальный сервис (нужен токен):
```bash
python -m lead_collector collect
```

Один день, один регион, контракты от 100 000 ₽:
```bash
python -m lead_collector collect --from 2026-10-19 --region 77 --min-amount 100000
```

Период:
```bash
python -m lead_collector collect --from 2026-10-01 --to 2026-10-19 --region 50
```

Разобрать архивы, скачанные вручную (без обращения к ЕИС — удобно, чтобы проверить разбор на настоящих файлах):
```bash
python -m lead_collector parse-folder путь\к\папке\с\zip --from 2026-10-19
```

Прочее:
```bash
python -m lead_collector stats                      # сводка: сколько всего, ООО, ИП, с телефоном и почтой
python -m lead_collector export                     # CSV и Excel (без «отказ» и «не беспокоить»)
python -m lead_collector export --all               # включая отказавшихся
python -m lead_collector status 7700000001 связались   # статус контакта
python -m lead_collector delete 7700000001          # полностью удалить поставщика по ИНН
```

Статусы контакта: `не связывались` (по умолчанию), `связались`, `согласие получено`, `отказ`, `не беспокоить`.

## Где что лежит

Всё в `data/` (папка в `.gitignore`, в git не попадает):
- `data/leads.sqlite` — база;
- `data/export/leads_ДАТА.csv` и `.xlsx` — выгрузки (CSV открывается в Excel; разделитель «;»);
- `data/collector.log` — журнал. В нём только числа, номера контрактов и названия файлов: **без** названий, телефонов, почты и ИНН.

## Как это работает

- Один поставщик — одна запись, ключ ИНН. Повторный контракт обновляет «последний контракт» (если он не старше прежнего) и счётчик.
- Каждый контракт запоминается; повторный запуск за тот же период ничего не меняет и дублей не создаёт.
- «Число контрактов» — сколько контрактов этого поставщика попало в базу за всё время сбора.
- Тип: ИП определяется по разметке (физлицо/ИП), по ИНН из 12 цифр, по названию; ИП помечены отдельным столбцом «Персональные данные (ИП)».
- Столбцы: источник (номер контракта), дата сбора, статус контакта.
- Паузы между запросами (`EIS_PAUSE_SECONDS`, по умолчанию 5 с), три повтора при сбое с нарастающей паузой, ожидание готовности архивов.
- **Удаление по ИНН** стирает карточку и все контракты поставщика и сжимает файл базы. Старые CSV/Excel удалите сами: в них ИНН мог остаться.
  После удаления при следующем сборе поставщик появится снова. Чтобы не получать его заново, не удаляйте его, а ставьте статус `не беспокоить` (он не попадает в выгрузку) — вопрос к юристу.

## Если ошибка

| Что видите | Что делать |
|---|---|
| `Не задан токен ЕИС` | Создайте `.env` с `EIS_TOKEN=...` (см. «Установка») |
| Сбой соединения / тайм-аут | Сайт ЕИС не открывается с вашей сети. Проверьте, открывается ли zakupki.gov.ru в браузере. Защиту и блокировки не обходим |
| Ошибка сервиса ЕИС, превышен лимит запросов | Подождите (лимит считается в час), уменьшите период, увеличьте `EIS_PAUSE_SECONDS` |
| `Архивы … не появились` | Архивы готовятся долго; повторите позже или увеличьте `EIS_ARCHIVE_WAIT_SECONDS` |
| Ошибка запроса / «валидации» | Формат запроса не проверен на настоящем сервисе: сверьте `client.py` и значения `EIS_SUBSYSTEM`, `EIS_DOCUMENT_TYPE` со схемой `getDocsIP-ws-api.xsd` |
| В выгрузке пустые телефон/почта | Возможно, не те названия тегов: проверьте `TAGS` в `parser.py` на настоящем XML (`parse-folder`) |
| «Не удалось разобрать файл …» в журнале | Один файл в архиве сломан; остальные обработаны |

## Ежедневный запуск

Запускать вручную раз в день или по расписанию Windows (Планировщик заданий): `python -m lead_collector collect` в папке `tools/lead-collector`.
Настраивать расписание — только после первого успешного ручного запуска на настоящем ЕИС.
