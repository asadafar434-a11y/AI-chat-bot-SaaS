# Статус проекта «Тендерный юрист»

Снимок на **7 октября 2026**. Это не журнал изменений (он — в `git log`), а ответ на вопрос «что уже готово
и что осталось» для следующего разговора с ИИ или с человеком, который откроет эту папку впервые.

Продукт — помощник для участия в тендерах по 44-ФЗ/223-ФЗ: загружает документы закупки, разбирает
требования, помогает выбрать цену, составляет техническое предложение и другие документы заявки,
проверяет комплект перед подачей. Раньше (до 23 сентября 2026) в этой же папке был другой проект
(support-чат), от него остались некоторые старые файлы и упоминания — ориентироваться на них не нужно.

## Как посмотреть вживую

Одна команда, один адрес `localhost:3000`:

```bash
npm --prefix web run build:host
npm --prefix web run start:local
```

(в приложении Claude Code — запуск `product` из `.claude/launch.json`). Для правок с мгновенным
обновлением экрана — см. [CLAUDE.md](CLAUDE.md), раздел «Дизайн-система».

## Что реально готово и работает

Проверено вживую в браузере и/или тестами 2026-10-07, если не указано иное.

**Путь по одной закупке (5 шагов, см. `web/src/lib/steps.ts`):**
- **Загрузка** — Word читается напрямую (структура файла, не просто текст), PDF — по линиям таблиц,
  Excel — по листам и ячейкам; у каждого куска текста есть точный адрес в источнике. Поиск по загруженным
  документам — локальный, без ИИ, реально работает.
- **Анализ** — требования заказчика раскладываются по пунктам закона; числа и сроки («не менее 150»,
  «в течение 10 дней») код вытаскивает из цитаты сам, а не ИИ — есть защита от «подстановки» (не путает
  границу заказчика со значением участника).
- **Цена** — нижняя граница, антидемпинг (ст. 37 44-ФЗ), размер обеспечения (ст. 96) — формулами,
  целиком в браузере, без ИИ.
- **Проверка** — сверка пунктов, подсветка пропусков. Составление текста техпредложения — через ИИ
  (сейчас не отвечает, см. «Что выключено» ниже).
- **Пакет** — сборка и скачивание файлов Word/PDF/ODT; плюс три отдельные проверки перед подачей, все
  видны прямо на экране: **комплектность** (детерминированная), **финальный аудит** (критичные замечания),
  **баллы по критериям заказчика** (код, без ИИ, с честной пометкой там, где формула не распознана).

**База доказательств компании** (в «Профиль компании») — ручное добавление факта работает; автопоиск
фактов в документах написан (реальный вызов ИИ), сейчас не отвечает без ключа.

**База знаний (RAG) и подбор норм закона** — построена из папки «Татьяна-Примеры документов» (золотой
стандарт + база знаний, см. `git log` от `e125979` до `4ac66e9` и далее) и живого текста 44-ФЗ/223-ФЗ
(`web/src/lib/law-pick.ts`, `web/src/data/laws/`). Хранится в PostgreSQL (`KnowledgeDocument`,
`KnowledgeChunk`), используется в составлении ТП, проверке требований и общем чате за флагами
`KB_CHECK=on` / `KB_DOCS=on` (сейчас включены в `web/.env.local`). Эта часть уже пишет/читает
PostgreSQL отдельно от основного переключателя «сервер вкл/выкл» (Этап 11) — ниже.

**Автоопределение бланков заказчика** — если в закупке есть свой бланк/анкета/приложение, приложение
подставляет данные в него вместо того, чтобы придумывать структуру (см. `git log` вокруг `9f91846`,
`bd1129e`, `d6a9e98`).

**ИИ-чат** (общий и по закупке) — написан по-настоящему: потоковые ответы, живой веб-поиск (реальный
инструмент Anthropic, не мок) в общем чате, сверка цитат модели с текстами законов, приём файла
(docx/pdf/rtf/xlsx/zip/txt/md/картинки). Сейчас без ключа отвечает честной заглушкой «ИИ пока не
подключён» вместо ошибки.

**Производственная архитектура (Этап 11)** — построена целиком и влита в `main`, вопреки старому плану
«отложить до готовности логики»: настоящая PostgreSQL-база, вход по логину с ролями (Auth.js), перенос
данных из браузера на сервер, серверное чтение/запись (dual-write), S3-совместимое хранилище файлов,
журнал аудита, фоновые задачи (pg-boss), резервные копии — всё протестировано, прошло финальную проверку
готовности («READY»). Живой статус по шагам S0–S11 — [docs/stage-11/process-log.md](docs/stage-11/process-log.md).

## Что сейчас выключено (и почему)

- **ИИ-ключ** (`ANTHROPIC_API_KEY` в `web/.env.local`) — закомментирован. Любая функция, которой нужен
  живой ИИ (чат, текст ТП, поиск фактов, распознавание сканов), отвечает честным «ИИ не подключён» вместо
  ошибки. Включать может только владелец — в сессии с ИИ есть правило не включать платный ИИ без явного
  «да» и цены в рублях.
- **Серверное хранение данных** — переключатели готовы и протестированы, но выключены:
  `NEXT_PUBLIC_SERVER_READS=0`, флаг записи не задан. Продукт сегодня реально хранит данные в браузере
  (IndexedDB), а не в Postgres — это сознательная настройка, не недоделка, включается флагом.
- **Оплата (Этап S10, ЮKassa)** — **заблокирована намеренно**: провайдер официально не выбран владельцем.
  В документации и `.env.example` ЮKassa — только предполагаемый вариант, не решение. Писать код оплаты
  запрещено, пока владелец явно не выберет провайдера и не определится с разовой оплатой/подпиской,
  способами оплаты, чеками (54-ФЗ). Подробности — [docs/stage-11/s10-payment-provider-freeze.md](docs/stage-11/s10-payment-provider-freeze.md).
  Из-за этого «Купить», «Заявка под ключ», «Проверка специалистом» на экране честно помечены «скоро».
- **Поиск закупок**, **импорт по ссылке ЕИС**, **итоги торгов в истории заявок** — показывают пример или
  честно написано «в разработке»; реального подключения к площадкам нет.

## Известные мелкие ограничения

- Ограничение частоты запросов и бюджет ИИ — пока в памяти процесса, не общие на несколько серверов
  (не мешает при одном сервере).
- Docker-образ ~2.16 ГБ — можно уменьшить, отложено.
- `docs/legal-rf/` — отдельный юридический пакет, намеренно не в git.
- Старый аудит безопасности/права — [AUDIT.md](AUDIT.md) (сверен на 27 сентября 2026, частично устарел
  по коммитам, но пункты про РФ-хостинг, уведомление Роскомнадзору, модель ИИ в РФ и юридические тексты —
  по-прежнему открытые решения владельца и юриста).
